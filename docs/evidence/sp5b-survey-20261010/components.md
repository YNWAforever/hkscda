- Evidence tags: **[V]** read in the code at the cited line; **[I]** inferred from a name or a neighbouring line, not read to the bottom; **[?]** not verified.
- Recurring cross-cutting facts (they explain many gaps below):
  - `fetchAdminJson` (`src/lib/admin/session.ts:93-129`) throws a plain `Error("API request failed")` for any non-2xx response whose body is not the structured `{error:{code,message}}` shape, and drops the HTTP status. Only structured errors and every path containing `/volunteers` become `AdminApiError` with a `.status` (`:109-122`). `requireAdmin` answers 401/403 with plain-text bodies (`src/lib/admin/session.server.ts:21,33,42,53,58`), so the browser cannot tell 401 / 403 / 404 / 5xx apart on most admin screens.
  - `new QueryClient()` has no defaults and no global `onError` (`src/router.tsx:6`). TanStack's default `retry: 3` therefore applies to every admin query (no `retry:` override found in `src/components/admin`, `src/routes/admin`, `src/lib/admin`); a failing query shows its loading state for several seconds before any error UI appears [I: default behaviour, not measured].
  - Production TSX in `src/components/admin` and `src/routes/admin` contains no hard-coded CJK strings (only tests do), so "words typed ad hoc" is already largely solved by SP-5a; what is left is visual (colour, component) not wording.
