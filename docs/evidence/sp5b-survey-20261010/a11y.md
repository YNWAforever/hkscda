## How the survey was done, and what it cannot tell you

- Copy: I imported all 78 bilingual copy modules (`defineAdminCopy`) with Bun and flattened both halves (4,097 zh leaf strings, 4,104 en).
  Button labels were found by a TypeScript-AST scan of the 164 admin `.tsx` files (`<Button>`, `<button>`, `AlertDialogAction/Cancel`, `DialogClose`, `*Button` components, `*Label` props), resolving each `copy.x.y` back to its key. About 450 label expressions resolved; 18 were data values (names, ids) and were dropped.
- Error text: "no next step" is a heuristic (no 請 / 重試 / 重新 / 再試 / 稍後 / 檢查 / 返回 and similar). I read the whole result list, but the count is approximate, and some messages sit next to a retry button that supplies the next step. Where I know that, the list says so.
- Target sizes are **estimated from Tailwind classes** (line-height + padding + border, or the explicit `h-*` / `min-h-*`). Nothing was rendered, no browser was run, no server was started. Class-less `<button>`s render with Tailwind preflight defaults (no padding), so about 24-27 px tall (`body` line-height is 1.7, `styles.css:231`).
- A5 (focus on the `h1`) was read from code only. There is no test for it and I could not run a device.
- Tests I ran (read-only): `adminTokenGuard`, `adminBrowserDataGuard`, `adminCopyGuard`, `adminErrorRenderGuard`, `adminRouteAuditing`, `adminAccessCoverage`. All pass. Two of them (`adminTokenGuard`, `adminBrowserDataGuard`) timed out at Bun's default 5 s on this Windows machine and passed with `--timeout 60000` (11 s). They scan the whole admin tree, so they are close to the limit.
