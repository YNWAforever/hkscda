## Failure and decision

The accepted guard refused `public.animals` with `Unsafe fixture default/constraint path: private.normalize_public_animal_age`. The stored generated expression is `private.normalize_public_animal_age(age)`. Read-only production metadata confirms `private.normalize_public_animal_age(p_age text) -> text`, postgres owner, PL/pgSQL, immutable, strict, invoker, exact config `["search_path=pg_catalog, pg_temp"]`, definition MD5 `1f85086f172d61fff31de8d854f32a55`, source MD5 `902aa35cba73b0cc25834c9f5ab1a78c`. Its full source uses lower/btrim/length/regexp_match, numeric casts/comparisons and unqualified regex; it has no query, scope mutation or external call.

The old procedure metadata query collected definition/source, language, schema/OID system identity, library/extension/version, owner and argument/result identity, but omitted `proconfig`. Its unqualified operator test compared every unreviewed same-symbol candidate across all schemas. An unrelated public `~` consequently tainted a function whose own scope resolves that symbol only in pg_catalog. PostgreSQL 17 explicitly excludes temporary schemas from function/operator lookup: [official search_path documentation](https://www.postgresql.org/docs/17/runtime-config-client.html#GUC-SEARCH-PATH).

The correction reads `proconfig` and permits core resolution only for the procedure's OWN exact singleton config above. It uses actual `prosrc`; any standalone `SET` or `RESET` token disables the exception conservatively, including comment-separated statements and unrelated UPDATE SET. Network/dynamic execution also disables it. Every matching pg_catalog operator candidate must exist and retain core schema/system/low-OID identity. High-OID or missing core candidates fail closed. Explicit qualified operators, transitive callee checks using their own scope, unknown calls, network primitives, seven native contracts, and stored expression dependency OIDs retain their existing checks. No caller scope is inherited by a callee.
