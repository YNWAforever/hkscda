# Isolated browser verification

Verified 2026-09-14 against the dedicated local application `127.0.0.1:56336`, Supabase API `56321`, and database `56322`. The complete results are in [browser.json](./browser.json).

- 50 page/role/viewport checks passed: 15 admin pages and 10 staff pages, each at 1440px and 390px. All have one workspace shell, one main landmark, one h1 and one active workspace link. No document overflow, browser page errors, failed page API reads, or serious/critical axe violations.
- 29 access checks passed: 24 API role checks and direct staff navigation denial for all five administrator-only settings pages.
- Five user journeys passed: admin/staff pending overview shortcut preserves the pending filter; admin/staff full email, partial email and name search find an email-verified, pending identity with zero bookings, then open its canonical qualification record; an unsaved policy name survives dismissed navigation and is discarded only after accepted navigation.
- Desktop and mobile policy comparison previews succeeded using an existing ready synthetic draft and a future Hong Kong effective date. These calls store local preview snapshots; no policy was published.

The verifier created one explicitly authorized, marked `@example.invalid` pending zero-booking identity because the isolated database had no pending profiles. It sends no email and leaves existing identities unchanged. The marked profile remains in the isolated database; its canonical ID and marker are recorded in `browser.json`. Auth sessions are refreshed locally without email. Page and role checks otherwise read real local APIs; policy publication, approval, attendance and booking mutations are outside this browser run.

Initial findings were corrected and rechecked: sidebar contrast, missing policy labels, duplicate active navigation, and the legacy reconciliation SQL read failure. Earlier harness-only failures came from a UTC date that was already the current Hong Kong day, an overly strict accessible-label locator, and a URL assertion that did not allow normalized query parameters. The final report contains the successful rechecks, not those superseded attempts.

Eight representative JPEGs (about 1.36 MB total) are retained here. Full quality-65 JPEG captures for every page remain in ignored `.local-policy-test/browser/volunteer-admin-centre`. The superseded PNGs generated by this audit were removed only from this evidence directory.

To repeat the full audit from the worktree in PowerShell:

```powershell
$env:VOLUNTEER_TEST_ALLOW_LOCAL_FIXTURES = '1'
Remove-Item Env:VOLUNTEER_AUDIT_PAGES -ErrorAction SilentlyContinue
node scripts/verify-volunteer-admin-centre.mjs
```

`VOLUNTEER_AUDIT_PAGES=settings` rechecks selected pages while retaining other page results and rerunning permissions and journeys. `journeys-only` reruns permissions and journeys. The script refuses any Supabase endpoint except the dedicated local stack and blocks browser traffic outside the two local origins.
