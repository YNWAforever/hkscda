# HKSCDA 全後台分組與動物分頁設計

日期：2026-09-14。
狀態：用戶已選方案 1（整個後台統一分組）；此書面規格待最後覆核，尚未修改功能。
基線：origin/main 8aabbf5（已合併 PR #121 義工營運中心）。
分支：feat/admin-navigation-groups，沿用既有隔離 worktree。

## 目的

將側欄由所有功能長清單改為六個工作範疇，範疇內以頁面分頁或既有工作區導覽選功能。最明確的改變是：側欄只有「動物管理」，頁內固定「貓貓｜狗狗｜助養」。保留現有業務操作、網址、角色權限、資料及新交付義工營運中心。

此方案整理整個後台的導航和共用操作體驗。另一個已評估方案只整合動物分頁，改動較小，但未涵蓋用戶要求的整體分組；用戶選擇完整分組方案。

## 資訊架構與現有入口對應

| 主要入口 | 現有功能歸屬 | 預設入口 |
| --- | --- | --- |
| 動物管理 | 貓貓、狗狗、助養動物；新增/編輯動物及詳情 | /admin?section=cat |
| 領養管理 | 收件箱、申請個案、手動建案、工作跟進、領養人、報表紀錄 | /admin/applications |
| 義工與實習 | 義工營運中心及全部子頁、團體查詢、實習申請 | /admin/volunteers |
| 捐款與助養 | 收款、助養承諾/配對/收款、支持者；現有收據仍由收款/承諾流程進入 | /admin?section=payments |
| 網站內容 | 宣傳內容、領養資訊、知識庫、常見問題、關於頁面、團隊與管治 | /admin/content |
| 系統設定 | 權限管理、付款方式設定、領養狀態設定；按原權限逐項顯示 | 使用者有權限的第一項設定 |

義工政策等領域設定保留在義工工作區，避免普通職員要離開工作流程才能找到相關說明。全站側欄不再重複列義工政策/團體查詢。新增動物、手動建案等建立操作亦有工作區內明確入口，不必依賴全站側欄。

「助養」動物分頁只代表既有 sponsorship-eligible 動物名單，不能把助養當第三種物種；既有助養承諾審批仍按 sponsorshipReview 權限可到達。捐款與助養工作區處理支持者承諾、配對及財務紀錄。名稱和說明讓動物名單與金錢紀錄容易區分。

## 共用導覽行為

- 桌面侧欄顯示最多六個主要入口、圖示及清楚選中狀態。每次只標記一個目前工作範疇；詳情頁仍標記正確父範疇。
- 進入範疇後有頁名、簡短說明、可到達的次級功能和麵包屑。常見功能使用頁內分頁；長功能清單沿用工作區內分組導覽，不重複全部全站側欄項目。
- 新全站導覽整合 PR #121 的義工工作區，保留其已驗證的子頁、角色導覽及未儲存草稿保護，不建立第三層重複側欄。
- 全站導航定義有單一真實來源；每個目的地含所需 access area 和可判定的 route/search matching。頁面守衛和 API/RLS 權限仍獨立執行。
- 沒有任何允許目的地的範疇不顯示。主要入口預設頁若無權限，導向該範疇第一個有權目的地；不先導向403再讓使用者自行找頁。
- 手機沿用可開關的導覽抽屜，選擇後關閉並移至頁面標題；頁內分頁可局部橫向捲動，整頁不可溢出。
- 保留現有中文/英文切換、側欄收合及登出；新增分組/分頁文案同步中英，zh-HK 為主。

## 動物工作區

頁首顯示「動物管理」及「新增動物」主要操作。下方永遠可見「貓貓｜狗狗｜助養」分頁，再下方是搜尋/篩選和既有動物表格。助養頁的動物/承諾審批切換保持可到達且清楚命名，不移除現有功能。

分頁分別沿用 /admin?section=cat、dog、sponsor。瀏覽器前進/返回可恢復分頁及該次URL中的篩選。搜尋、篩選和頁碼在各分頁切換时保留其各自狀態；查詢鍵包含實際篩選值。可使用工作區元件內的每分頁状态映射搭配經驗證URL參數，不儲存個人資料到localStorage。登出後不得沿用其他帳戶的查詢快取。

保留同一 canonical 動物記錄及既有 adminAnimalFilter，不能複製動物來呈現助養。新增/編輯/刪除及照片工作流保持既有權限和審計。錯誤顯示重試，未讀到資料不能顯示「沒有動物」；篩選無結果與真正空名單分開說明，並提供清除篩選。

## 架構與範圍

保留 TanStack Start、React、TypeScript、Supabase、Bun 及現有品牌 semantic tokens。主要實作位置為 adminNav、AdminLayout、adminI18n、動物 dashboard/AnimalsTable 的導航狀態，以及相應工作區的頁內入口。共用導航模型負責分組及路徑判斷；共用元件負責顯示；現有頁面和server service繼續執行业務行為。

此改動不重設各領域的審批/付款/CMS表單或資料模型，不新增資料庫遷移、不改政策、不修改正式資料，也不新增虛構的待辦數字或收據總覽。現有收據使用現有流程入口，不能為導覽演示建立沒有後端的新頁。

所有舊網址和書籤繼續有效，包括 /admin?section=cat/dog/sponsor/payments、所有領養/內容/義工內頁及深層詳情頁。即使從舊網址直接進入，新導航亦須顯示正確範疇。

## 驗收

1. 導覽模型測試：每個既有目的地有歸屬、每個可存取路由有且只有一個主要選中範疇；staff/treasurer/admin 的入口皆符合原 role matrix，沒有意外擴權。
2. 動物旅程：貓→狗→助養切換、搜尋/狀態及頁碼恢復、前進/返回、舊網址直接開啟、新增/編輯入口、助養承諾審批可到達。保留物種與助養資格篩選差異。
3. 其他範疇：逐一檢查上述全部原有入口及子頁能到達；財務角色進入有權頁，職員不會看見僅管理員可用的設定。
4. 回歸 PR #121 義工子頁：沒有重複全站外框/選中狀態，既有未儲存政策在導航切換時仍可取消離開。
5. 桌面1440px與手機390px驗證標題、焦點、鍵盤分頁操作、抽屜關閉、觸控目標、無整頁溢出及沒有 serious/critical axe 問題。
6. 執行 typecheck、Bun測試、lint、build及適合的既有回歸檢查。使用專用本地資料及synthetic角色，不能以正式動物/支持者/金錢/出席資料做變更fixture。
7. 交付逐範疇前後說明、代表截圖、權限與瀏覽器證據及獨立PR。正式合併/部署仍需另行release approval；此設計批准不代表發布批准。

## 自查

六個主範疇已涵蓋既有全站側欄目的地；領域設定與全站設定邊界清楚；既有網址/角色及助養動物與財務分工保留；不新增沒有對應實作的產品入口。PR #121 已合併並作為新基線，無需重做或重播其資料庫遷移。
