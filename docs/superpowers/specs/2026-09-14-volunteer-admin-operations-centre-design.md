# 義工營運中心 UI/UX 設計

日期：2026-09-14
狀態：用戶已批准規格及實作；候選已實作，驗收及正式發布限制見 docs/evidence/volunteer-admin-centre/README.md。

## 目標與範圍

將 /admin/volunteers 及所有現有內頁整合成一致的營運工作區。職員能找到尚未報名的義工、核實資格、處理場次和報名、查閱事實紀錄；管理員能清楚編輯、比較和發布現有版本化政策。

已採用完整營運中心方案。保留結構只改外觀的方案不能解決名冊與報名混淆；月曆優先方案則不適合作為身份核實入口。

沿用 TanStack Start、React、TypeScript、Supabase、Bun、zh-HK 及既有品牌 semantic tokens。保留所有 canonical IDs、資料、照片及歷史。此次不包含實習、財務或其他後台模組重設，也不改變義工業務政策。

## 統一工作區

在現有 AdminLayout 內建立共用 VolunteerAdminShell，所有義工路由只呈現一次全站外框。桌面呈現分組導覽，手機呈現可展開導覽，並有目前位置、麵包屑、頁名、簡短說明及主要操作。

導覽分為：

- 營運：總覽、義工名冊、活動與報名、月曆、今日待辦、團體查詢與改期。
- 管理員設定：場次政策、全日配額、級別評核、場地與資格、政策模擬。

沿用現有 role matrix：staff/admin 可處理營運；設定、來源、模擬、每日配額和評核僅 admin 可進入。treasurer、一般義工及匿名使用者不得存取。導覽隱藏僅改善體驗，API 仍逐次核實身份和權限。

視覺統一為品牌藍主操作、語意化狀態標籤、清楚的文字層級、44px 主要觸控目標及足夠間距。表格保留比較能力，窄螢幕改卡片或受控局部橫向捲動，不能使整頁溢出。鍵盤焦點、表單標籤、對話框返回焦點及 reduced motion 均納入驗收。

## 資料與元件邊界

共用 shell 只處理導覽與版面；directory read model 負責名冊、分頁及身份資料；個人紀錄 read model 以 canonical profile ID 關聯報名和事實紀錄；各既有 mutation service 繼續執行領域規則。

新增資料需求走薄 API → 身份/角色及 schema 驗證 → service → repository。電郵由伺服器限定連結至 volunteer_profile 的 auth user 讀取，僅返回名冊需要的欄位；不可將 auth.users 或 service key 暴露到客戶端，也不可逐頁列出所有 Auth 帳戶後在瀏覽器過濾。搜尋有長度限制、字面匹配、穩定排序及最多 50 筆分頁，並有總數。無帳戶連結的舊身份顯示「未連結」，不按猜測合併身份。

總覽統計與列表使用一致狀態定義和 Asia/Hong_Kong 日界。缺額依目前權威政策計數，不以 UI 常數估計。某個區塊失敗獨立顯示錯誤及重試，不能顯示假零。無可計算政策時明示狀態。

所有設定表單有 typed draft、欄位及整體驗證、未儲存提示、提交期間防重複、成功回饋及 revision 衝突提示。不可自動重送具副作用的命令。衝突提供重載與重新核對，不能覆蓋較新修改。

查詢鍵含篩選、頁數或 profile ID；mutation 成功後刷新相關列表、詳情和總覽。HTTP/API 失敗保留使用者輸入。

## 不可破壞的規則

伺服器仍執行目前權威政策、原子容量/審計、冪等、避免重複有效報名、避免已確認職務重疊、有效參照及不可改寫事實歷史。職員不能用 UI override 繞過政策。普通管理員沿用明確版本發布流程，不增加第二批准人。

如新查詢需要 SQL，只新增 forward migration、最小 service_role 權限及 pinned search_path；不得重播 production migrations。提供本地遷移前後與相容回退證據；若無需 SQL 則明示沒有資料庫遷移。

## 驗收與交付

1. 以隔離測試身份重現「已驗證電郵、待核實、零報名」，按完整電郵、部分電郵及姓名都能找出，不能使用真實 Willy 帳戶作變更 fixture。
2. 名冊涵蓋同名、舊身份未連結、空名單、搜尋無結果、超過一頁及查詢失敗；驗證總數、分頁與穩定排序。
3. staff/admin 完成查找 → 詳情 → 既有核實 → 報名審批 → 出席 → 紀錄旅程；匿名、義工、treasurer 與 staff 對 admin-only API 的負向權限驗證通過。
4. 所有上表頁面在桌面及 390px 手機驗收導覽、空白/失敗/載入、鍵盤、表單及回饋；檢查無整頁橫向溢出和重大 axe 問題。
5. 管理員草稿儲存、差異比較、模擬、發布及 revision 衝突使用隔離資料驗證。測試不送真實郵件、不扣款、不改正式身份、政策或出席。
6. 執行 typecheck、Bun tests、lint、build、品牌檢查及相應 DB/API 測試。報告實測、mock 與未驗證項目，不把 mock 結果當成真實整合驗收。
7. 提供逐頁完成表、瀏覽器證據、必要遷移/回退證據及可審查 PR。此次選擇是設計方案批准；正式合併/部署仍遵守 repo 的另行 release approval 規定。

## 實作切片順序

共用外框及導覽 → 名冊/個人詳情與受限查詢 → 總覽及活動/報名 → 月曆/團體/待辦 → 全部設定內頁 → 跨角色驗收與 PR。各切片都交付可用資料流，不留下僅外觀可操作的按鈕。

## 規格自查

已涵蓋現有 12 類路由及新增名冊/活動頁；角色邊界與原有 access matrix 一致；沒有待定業務政策、第二批准人或真實資料 fixture。正式發布權限不由此設計確認推定。
