# Background jobs runbook

The background jobs are seven scheduled tasks that Vercel runs by itself: they send emails, build exports, clean up expired uploads and repair media. As of 2026-10-08 none of them has ever run in production, because `CRON_SECRET` is unset and every job refuses a request that does not carry it.

## Jobs

| `/api/jobs/crm-exports`         | every 5 min          | Builds requested supporter and donation CSV exports                                                                                                                                                                          | Queue empty. - Deleted uploads are expired and were never submitted. Deleting them is the jobs' purpose and the privacy-correct outcome.
- The volunteer and sponsorship jobs record their database changes as the actor user set below.

## Switch-on, in order

1. In Vercel, go to Project `hkscda` → Settings → Environment Variables (Production), and then:
   - Set `RESEND_API_KEY` and `RESEND_WEBHOOK_SECRET` from the Resend dashboard (the webhook secret is the signing secret of the Resend webhook endpoint).
   - Set `APP_URL` to the domain production serves today.
   - Confirm `NOTIFICATION_EMAIL`.
2. Set `VOLUNTEER_JOB_ACTOR_ID` to the auth user UUID of an active admin. Find it under Supabase → Authentication → Users; that user must have an `admin_user` row with role `admin` and status `active`. Set `SPONSORSHIP_JOB_ACTOR_ID` to an active staff, admin or treasurer auth user UUID. One active admin can serve as both.
3. Generate a long random value locally. On Windows 11, paste this into the Windows PowerShell 5.1 that comes with it: `$b = New-Object byte[] 32; [Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b); ($b | ForEach-Object { $_.ToString('x2') }) -join ''`. In PowerShell 7.2 or newer, `[Convert]::ToHexString([Security.Cryptography.RandomNumberGenerator]::GetBytes(32))` also works, and so does `openssl rand -hex 32` where `openssl` is installed. Add the value as `CRON_SECRET` (Production, Sensitive), with no spaces around it, and share it with no one.
4. Redeploy production, because environment changes apply only to new deployments. In Vercel, go to Project `hkscda` → Deployments → the latest Production deployment → the ⋯ menu → Redeploy.

## Verify, and pause if needed

- Within about an hour, Vercel runtime logs show no `CRON_SECRET is not set in production` error.
- In Supabase (Table Editor), `volunteer_runtime_job_run` has a row for the current hour with status `complete`. If the row is `failed`, read its result. `volunteer_job_actor_missing` means the UUID is not an active admin. `job_failed` is what an empty or malformed value records, but it is also the generic name for any other database error. Recheck step 2 first.
- In Vercel, under Settings → Environment Variables, `SPONSORSHIP_JOB_ACTOR_ID` is set for Production. Then, within about an hour, open the Vercel runtime logs for `/api/jobs/sponsorships`. A 200 is expected. The job reports `disabled` when the actor is not set, `queued` (leaving any queued deliveries untouched) when `RESEND_API_KEY` is not set, and `processed` otherwise, even when the queue is empty. A 500 means the run failed. With `RESEND_API_KEY` set, the usual cause is that the `SPONSORSHIP_JOB_ACTOR_ID` user is not an active staff, admin or treasurer, and the job then fails again every hour until you fix step 2 and redeploy.
- In the admin, export a supporters or donations list that matches more than 5,000 rows. The admin then offers "Create background export" ("建立背景匯出"), and the file becomes ready within about five minutes. If no list is that large, skip this check: smaller exports never use the job.
- The next day, the three daily jobs show 200 responses in the Vercel logs. Check `public-media-repair` on day one in particular.
- **To pause everything:** remove `CRON_SECRET` and redeploy. The missing-secret error then appears in the logs, which is expected. While `CRON_SECRET` is removed, creating a background export also answers 503 and `/api/internal/readiness` answers 401, so the live-readiness check (`scripts/verify-live-readiness.ts`) cannot run until the secret is restored.
- **To pause one job:** remove its entry from `vercel.json`, add its path with the reason to `INTENTIONALLY_UNSCHEDULED` in `src/lib/cronScheduleContract.test.ts` in the same commit, and deploy. For sponsorships only, removing `SPONSORSHIP_JOB_ACTOR_ID` and redeploying also works.
