### Review-fix behaviour

- The selected persisted release is compared with the local draft and the authenticated preview release ID/version. Submit and publish require a clean draft, a successful matching preview, and ready status; dirty drafts show the save-then-refresh guidance.
- A successful save invalidates and refetches release and exact-preview queries, so the view baseline resets from persisted data and stale previews cannot unlock transitions.
- All asset pages are fetched with a bounded loop; release list page controls use the server `total`, `page`, and `pageSize` values. Filters and selection are disabled while a mutation is pending.
- Publish invalidates release, document, and knowledge queries; the existing ref-held publish attempt keeps retry idempotency stable for the selected release version.
